# W4-05 expense, reimbursement and protected sales billing

2026-10-01. Additive synthetic development; no installation authority is implied.

Expenses use one scoped project, employee and immutable revision. Up to fifty
ordered task weights allocate the original converted gross using cumulative
half-even rounding. Original net plus tax equals gross; base gross and net are
converted once with the installed dated exchange-rate record, and base tax is
their difference. The original published tax/rate versions, names, rational
numerator/denominator and conversion residue remain available to cost-authorized
reviewers. Independent approval freezes the revision and creates one expense
ownership claim. Supplier AP remains unavailable until its installed provider is
verified. Reimbursement uses a separate base-currency obligation with original
journal effects, partial recorded settlement and exact original-effect reversals;
neither journal posting nor settlement recording executes a bank payment.

Private attachments remain explicitly unavailable: no generic file grant, URL,
bucket path or private document is accepted as expense evidence. A bounded
synthetic evidence reference is attributable metadata. A future protected
attachment adapter must prove per-expense authorization before activation.

Expense, reimbursement, settlement, billing and margin capabilities are separate.
Every API checks current module entitlement, membership and branch scope; commands
and private views require MFA. Generic receipts contain IDs, status and version
only. Original values, source bodies and cost amounts stay in protected tables.

Billing reserves one to two hundred whole approved units under sorted locks and
uses the installed sales invoice upsert API with quantity/base quantity exactly
one. The selected active service product and base UOM, prices, tax version,
customer, currency, date and original source digests are frozen. Existing sales
workflow APIs decide and post using their real authorized actors. Protected
invoice links block ordinary financial/line edits; a private transaction-bound
posting-intent table guards direct sales posting. Client-settable session settings
are never authorization. Posting consumes all original units atomically with the
installed invoice/journal and the module receipt. Cancellation releases only
unposted reservations. Original posted units remain consumed after credits.

As-of reports use both effective service/posting dates and recorded timestamps.
Posted invoice revenue and linked original credits are distinguished from
unposted drafts. Approved expense/time cost, open reimbursement obligations,
approved capacity commitments, budget and unbilled sources retain source drill
down. Closure rejects editable expenses, unpaid obligations and unposted batches.
All pages are at most fifty rows. Native forms use named scoped selectors and
encrypted actor/scope/action recovery, retaining exact uncertain requests and
known confirmations before optional reads.

Verification must prove API-only forced RLS, independent approvals, changed-body
replay rejection, scope/MFA/revocation, exact allocation and obligation
conservation, sealed linked invoice edits/direct posting, closed-period and late
failure atomicity. Candidate rollback, client tests/builds, rendered review,
installation, true concurrent sessions, native authentication/restart and owner
acceptance are separate evidence categories.
