# Wave 5 governed control contracts

The October 6 request to finish the remaining work authorizes additive development. These contracts define the provider-neutral logic for W5-04 through W5-07 before implementation. They do not authorize installation, secret issuance, real subscriptions, model calls, external delivery or operator grants.

## W5-04: AI evidence and proposals

Retrieval version 1 accepts only the redacted numeric `pipeline.current_weighted.v1` projection. Scope and live source authorization are established by a trusted adapter before retrieval and again before provider invocation. Evidence contains source UUID/version/hash, currency, amount, probability and date. Free-text source fields, actor names, HR, credentials and payment details are excluded. Evidence is data: it cannot select tools or command codes. An absent model provider returns `PROVIDER_UNAVAILABLE`; no generated output is invented.

Proposal policy version 1 permits only `analytics.freeze_pipeline.v1`, with two exact ISO dates, a frozen forecast source reference/hash, exact positive source revisions, a generated command identity, bounded resource estimate, creation time and expiry within 24 hours. No SQL, arbitrary command or editable executable free text is accepted. Submitted revisions are immutable; editing creates a new revision and requires a new decision. A human approval binds the proposal ID/revision/hash. Online status, distinct proposer/approver, live `ai.proposals.approve`, MFA and expiry are required. Execution rechecks those constraints, every target revision, scope, source capability/entitlement and quota before invoking the existing named command with the proposal's stable identity. An injected trusted dispatcher is required; the pure validator cannot grant authorization. Provider outcomes use explicit `pending`, `settled` and `unknown` identities; unknown usage cannot release a reservation or silently start another invocation.

## W5-05: webhook and external API boundaries

Webhook contract 1 permits only `analytics.forecast.frozen.v1`. Its payload contains stable event UUID, tenant/entity/branch, forecast UUID, definition revision and source hash. No raw outbox payload, audit context, private business text or credentials may be copied. A worker must establish the event is committed, currently permitted and matches the configured subscription scope. Deliveries preserve one event/subscription identity and distinct attempt identities; maximum eight attempts use capped exponential retry intervals. Success means a verified 2xx acknowledgement for that attempt; it does not promise exactly-once consumer effects. Dead letters and explicitly authorized replay remain append-only evidence.

Destinations must be HTTPS on port 443, without userinfo or fragments, and have a reviewed hostname allowlist. Every DNS answer must be globally routable; localhost, private, link-local, loopback, multicast, reserved/test, metadata and IPv4-mapped private IPv6 are rejected. A reviewed transport must connect to a validated resolved address with the original TLS hostname, disable redirects, revalidate on every attempt and prevent DNS rebinding. A pure destination check is not a secure transport. HMAC-SHA256 signs the exact serialized payload plus timestamp/event identity with server-held versioned keys. Keys never enter desktop models or logs.

External API contract 1 permits only the existing named forecast command. A trusted gateway validates credential hash, live revocation/expiry, exact tenant/entity/branch, named capability, schema revision, entitlement, throttle/quota reservation and stable command identity before dispatch. Credentials and service role are server-only. Missing credential/worker providers return unavailable; client claims cannot substitute for them.

## W5-06: synthetic billing and metering

The existing `billing.tenant_subscriptions` and `billing.plan_entitlements` remain authoritative. Effective-dated immutable revisions record synthetic plan/trial/seat decisions and commands; they do not create another entitlement resolver. Trial intervals are half open, explicit and bounded. Real billing collection is excluded. Owner-authorized installation must identify the synthetic tenant and privileged actor before any plan mutation is exposed.

Usage contract 1 uses exact nonnegative integer quantities, unique trusted event/invocation identities, an explicit half-open billing period and append-only reasoned corrections linked to one original event. No client usage report is authoritative. Corrections cannot reduce an original event below zero and duplicate correction identities are no-ops only when the entire payload matches. Hard quotas require a trusted server row lock or equivalent atomic storage transaction: reserve only when settled usage plus outstanding reservations plus requested amount is at most the live hard cap. Settlement cannot exceed its reservation; unknown outcomes keep their reservation. Retry identities bind the original amount/scope/period. Pure allowance arithmetic is not contention proof.

The synthetic subscription candidate adds an explicit trial-start column to the existing billing row. Its immutable reason code is `synthetic_trial_review`. No target is allowlisted automatically. Schedule requires global `billing.synthetic.manage`, live MFA and an expected billing version; activation rechecks the original actor's current membership/capability and verified MFA factor. Active and invited memberships consume seats; accepting another member takes the same billing-row lock as activation and usage reservation. Trial periods cannot overlap an existing quota period. Unapplied trigger behavior is confined to explicitly allowlisted synthetic tenants. Sequential fixtures do not prove contention safety.

## W5-07: operator isolation

Operator policy 1 is a separate server authority. Tenant roles, including owner, cannot grant it. Health exposes only generated probe times, supported contract revisions and bounded lag/retry/dead-letter/quota/readiness aggregates. Missing or stale probes are `unknown`; no business rows or raw worker errors appear. Selected-tenant access additionally requires a reasoned, explicitly issued, unexpired MFA-protected grant for the exact operator and tenant; each access is audited. No operator is bootstrapped by this candidate, and no service-role credential enters Flutter.

## Native and verification contracts

Each provider advertises its exact contract revision and readiness. Native source evidence must be cleared on actor/context/connectivity/access loss and late reads must be discarded. Filters/scenarios and uncertain command envelopes reuse encrypted actor/context-bound recovery with live authorization before decryption/replay. Views distinguish unknown, denied, stale, conflict, valid empty and unavailable. Domain/adapter tests, rollback SQL, rendered variants, Windows build, installed authenticated runtime, real workers, independent-session quota contention, target-scale latency and owner acceptance remain separate gates under AC-507 through AC-517.
