# Wave 5 reviewed model native contract

October 9, 2026. Additive implementation only; this contract does not authorize model configuration, deployment, provisioning or provider calls.

Jentra Control requests a suggestion from `wave5-runtime/model/suggestion` through the ordinary connected Supabase client. The client uses only its own current actor/session and selected tenant/entity/branch. No credentials, prompts, model key, service role or business text enter the request or recovery store. Server retrieval remains the allowlisted numeric `pipeline.current_weighted.v1` projection under the caller's current source authority.

The encrypted `model` recovery namespace stores one bounded original envelope per actor and exact scope. `commandId` is the invocation ID; `idempotencyKey` is the usage event ID. Its four string parameters are frozen source forecast UUID, token reservation from 1 through 2000, and explicit half-open quota-period start/end UTC. The client timestamp is retained as recovery metadata, not model or usage authority. Client dates cannot substitute for the server's authoritative quota period.

Live authorization compares the returned server actor before encryption, before recovery and after reading the encrypted draft. The gateway checks current actor and forecast scope before invocation, then rechecks actor, source access and exact source hash after the response. Its response schema permits only the named forecast-freeze suggestion, matching source UUID/hash and exact horizon. Generated token counts, free text, arbitrary commands, altered scope or horizon cannot enter the native suggestion view. Worker errors expose an allowlisted code and static explanation, never raw provider details.

The original is saved before sending. An uncertain, pending or unknown outcome retains that original and its reservation; another request cannot replace it. Reopen repeats the original invocation and usage identities. The persistent worker returns already settled output or requires review; it cannot silently send a second call for a pending/unknown invocation. Only a verified successful suggestion exposes Finish suggestion review, which removes the saved envelope after live authorization. Transport abort at 70 seconds remains an uncertain outcome, not evidence that the provider never ran.

The source-selection action only fills the separate human proposal form. It issues no proposal or business command. Explicit human submission creates a human-origin immutable proposal with zero model units in that proposal; actual model tokens remain separately settled by the trusted worker. The existing distinct MFA approval and execution lifecycle is unchanged. A suggestion never grants approval or execution authority.

Actor, auth-session, capability or scope changes dispose the native controller. Offline transitions clear protected suggestion and pending display, discard late responses, and leave ciphertext available only after restored live authorization. Results are not cached as recovery bodies. A controlled controller restart or widget test is not real native process restart, actual provider usage or authenticated MFA acceptance.

Focused gateway, recovery, composite Control and rendered checks remain distinct from the separately reviewed installed/hosted/native/contention/load/owner gates.
