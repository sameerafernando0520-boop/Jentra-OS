## Boundaries of this review

**Transport and overlap.** Verified TLS precedes body dispatch; aborted, expired or failed queued requests cannot send later. Each genuine session requires a distinct connection. Client HTTP interval overlap is measured; backend server execution overlap is not inferred.

**Auth and MFA.** Source requires online Auth identity and matching committed server session/factor evidence, with 2,000 distinct session identities for the reviewed load population. Controlled tests are not genuine sign-in or MFA evidence.

**Secrets and public evidence.** Public outcomes whitelist identity, counters, safe codes and hashes. Raw API errors, private session values and invitation tokens stay outside the public case journal. Recovery tokens may only enter the separately reviewed private preparation sink.

**Fixture restoration.** Exact newly reviewed memberships, original roles and assignments are retained. The seat cap is raised before reactivation; versions and immutable history are not rewound or deleted. Unknown outcomes stop automatic restoration. Restart reconciliation still requires the actual private journal/factory review.

**Encrypted recovery persistence.** Public sink source uses AES-256-GCM with the bound envelope as authenticated data, copied private keys, exclusive new files, actual file-content sync and bounded read-only recovery. Recovery is an incomplete available prefix unless its copied expected head matches the separately retained count and final storage hash; even a complete read never permits automatic replay. An independent real temporary-file tail-loss test verifies this behavior and preserves the surviving bytes. The configured private key, directory ACLs, trusted head and Windows directory-entry/power-loss durability remain unverified.

**Reviewed caps and unsupported boundaries.** The immutable reviewed caps remain unchanged. 10001Rows and 8MiBPlus1Byte are unavailable under those caps; 101Groups needs reviewed reference evidence. The separately linked saved runtime evidence has an actual 367-day LIMIT_EXCEEDED response; this source review executes no new runtime boundary call.

**Management API bridge.** The fixed project endpoint accepts only scoped, typed SELECT recipes, verifies TLS and actual read-only/isolation metadata, and explicitly reports committedTransactionProof=false and repeatableReadProof=false. It cannot replace the PostgreSQL provider needed for committed contention evidence.

**Persistent workers and model usage.** No complete remote outbound observer is implemented or independently verified. Ingress logs and database attempt rows cannot establish actual delivery/model sends or complete timed-window coverage. Zero sends are not fabricated from empty rows.

The generic Management query endpoint documents typed parameters and `read_only`; it does not promise a repeatable-read transaction COMMIT. The official MCP source forwards those fields to that endpoint. This supports retaining the bridge’s explicitly false committed/repeatable-read proof fields. See [Supabase query API](https://supabase.com/docs/reference/api/v1-run-a-query), [official MCP source](https://raw.githubusercontent.com/supabase/mcp/main/packages/mcp-server-supabase/src/platform/api-platform.ts) and [separate read-only API](https://supabase.com/docs/reference/api/v1-read-only-query).
