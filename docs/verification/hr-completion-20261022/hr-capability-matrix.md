# HR employee capability gates — 22 October 2026

This is a read-only review of the current employee gateway, function/capability searches across all 130 repository SQL migrations with focused reads of the cited contracts, and the [employee mobile blueprint](../../blueprint/mobile-apps/EMPLOYEE_APP_BLUEPRINT.md). It establishes repository implementation, not installation or availability in hosted project `xpdoufauvrbdmxgngetv`. No hosted schema, grants, policies, functions, worker readiness or account data were inspected by this audit; the older 9 October live note is not current proof. No backend or app changes were made for this document.

The current mobile [`EmployeeGateway`](../../../apps/jentra_employee/lib/src/data/employee_gateway.dart#L257) exposes sign-in/out, workspace selection, accepted identity, pending account links, shared reviews, command execution and own command receipts. Its concrete implementation uses the foundation gateway and private HR gateway. It has no attendance, leave submission/balance, payslip, document, HR-case or notification method. The mobile screen labelled Inbox currently opens shared review actions; it does not read `api.my_notifications`.

## Existing employee slice and review gate

Identity uses `api.people_hr_self` ([private HR SQL:444](../../../supabase/migrations/20260929224939_wave4_private_hr.sql#L444)); pending link onboarding uses `people_hr_link_inbox`:429 and `people_hr_command`:482; review receipt recovery uses `people_hr_own_receipt`:802. These are wired by mobile gateway methods at source:392, 405, 425, 486 and 494. `people_hr_reviews`:372 has an accepted-link/self branch that excludes draft reviews, but accounts with broad `people.reviews.view` take the staff branch. The mobile gateway filters loaded results to its resolved employee and reviewed/acknowledged/closed states at source:425–461. A dedicated server employee-review projection remains necessary to make that publication boundary independent of app filtering for dual-role accounts.
